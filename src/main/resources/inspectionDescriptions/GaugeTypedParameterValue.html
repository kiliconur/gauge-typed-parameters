Reports Gauge step parameter values that the resolved Java step implementation cannot accept.

The step invocation is resolved to its @Step-annotated Java method, the placeholder under the value is mapped to the matching method parameter, and the value is checked against that parameter's type:

  • enum - the value must be one of the declared constants. A quick fix offers the closest matching constants.
  • boolean / Boolean - only true and false are accepted.
  • numeric types (int, long, short, byte, double, float, their box types, BigInteger, BigDecimal) - the value must parse as a number.

Example of a reported problem:


enum Element { LOGIN_BUTTON, LOGOUT_BUTTON }

@Step("<element> elementine tiklanir")
public void click(Element element) { }


* "LOGNI_BUTTON" elementine tiklanir     <- Unknown Element value 'LOGNI_BUTTON'

Nothing is reported while the project is indexing, when the step implementation cannot be resolved, when it resolves ambiguously, when the number of Gauge parameters does not match the number of Java parameters, or for any other parameter type (including String).
